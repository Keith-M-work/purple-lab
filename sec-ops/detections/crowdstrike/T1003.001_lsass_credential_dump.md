# CrowdStrike — LSASS Credential Dumping (T1003.001)

**Technique:** T1003.001 — OS Credential Dumping: LSASS Memory
**Tactic:** Credential Access (TA0006)
**Platform:** Windows
**Author:** Keith M · **Version:** 2.0 · **Updated:** 2026-07-24
**Data source:** Falcon endpoint telemetry via NG-SIEM / LogScale
**Primary language:** CQL (CrowdStrike Query Language)

> Falcon does not expose Sysmon-style `GrantedAccess` handle masks, so LSASS
> coverage on CrowdStrike is behavioural: process execution, module load and
> file-write telemetry rather than handle-rights arithmetic. Detections below are
> CQL. Custom IOA equivalents are in the appendix for endpoint-side prevention.

---

## 1. Primary — dumping behaviours (CQL)

```cql
// LSASS credential dumping — Falcon NG-SIEM / LogScale
// Classifies each hit so triage sees the technique, not just a match.
#event_simpleName=ProcessRollup2 event_platform=Win
| case {
    // rundll32 comsvcs.dll MiniDump — also matches the #24 ordinal form
    FileName=/^rundll32\.exe$/i
      and CommandLine=/comsvcs/i
      and CommandLine=/(MiniDump|#\s*\+?\s*24)/i
      | technique := "comsvcs_minidump" ;

    // procdump against lsass (rename-tolerant: checks the command line too)
    CommandLine=/procdump/i and CommandLine=/lsass/i
      | technique := "procdump_lsass" ;

    // named dumping tooling — matched on command line so renaming the PE
    // does not evade
    CommandLine=/(nanodump|handlekatz|dumpert|pypykatz|lsassy|mimikatz|sekurlsa|safetykatz|sharpdump)/i
      | technique := "known_dumper" ;

    // API-style live dump referencing lsass
    CommandLine=/lsass/i and CommandLine=/(MiniDumpWriteDump|CreateDump|--live|-accepteula)/i
      | technique := "api_dump" ;

    // taskmgr / explorer "Create dump file" against lsass
    FileName=/^(taskmgr|procexp\d*)\.exe$/i and CommandLine=/lsass/i
      | technique := "gui_dump" ;

    * ;
  }
| technique=~/.+/
// Suppress the known-benign crash-reporting path
| ParentBaseFileName!=/^WerFault(Secure)?\.exe$/i
| groupBy(
    [aid, ComputerName, UserName, ParentBaseFileName, FileName, technique],
    function=[count(as=hits), collect([CommandLine, SHA256HashData])]
  )
| sort(hits, order=desc)
```

## 2. Correlation — dump execution followed by a .dmp write (CQL)

Higher fidelity than either signal alone: the tool ran *and* produced an artifact.

```cql
// Chain: LSASS dump command → .dmp file written on the same host
#event_simpleName=/^(ProcessRollup2|DmpFileWritten|NewExecutableWritten)$/ event_platform=Win
| case {
    #event_simpleName=ProcessRollup2
      and CommandLine=/lsass/i
      and CommandLine=/(comsvcs|procdump|MiniDump|nanodump|handlekatz|dumpert)/i
      | stage := "dump_exec" ;
    #event_simpleName=DmpFileWritten and TargetFileName=/\.dmp$/i
      | stage := "dmp_write" ;
    * ;
  }
| stage=~/.+/
| selfJoinFilter(field=[aid], where=[{stage="dump_exec"}, {stage="dmp_write"}])
| groupBy(
    [aid, ComputerName],
    function=[count(as=events), collect([stage, FileName, CommandLine, TargetFileName])]
  )
```

## 3. Hunt — LSASS as parent process (CQL)

Rare and worth eyeballing; keep as a hunt, not an alert.

```cql
#event_simpleName=ProcessRollup2 event_platform=Win
| ParentBaseFileName=/^lsass\.exe$/i
| FileName!=/^WerFault(Secure)?\.exe$/i
| groupBy([aid, ComputerName, FileName], function=collect([CommandLine]))
```

## False positives

- **WerFault.exe / WerFaultSecure.exe** legitimately dumps a crashing LSASS — filtered above.
- AV/EDR, backup and DLP agents touch LSASS by design.
- IR tooling and purple-team exercises, including this lab's own validation runs.

## Validation (this lab)

From the Attack VLAN against a Falcon-instrumented endpoint:

```
rundll32.exe comsvcs.dll, MiniDump <lsass_pid> C:\Windows\Temp\lsass.dmp full
procdump64.exe -accepteula -ma lsass.exe out.dmp
```

## Appendix — Custom IOA rules (endpoint-side prevention)

Optional. Use when you want Falcon to *block* rather than just surface. Console
path: Endpoint Security → Custom IOA → Rule Group `Credential Access — LSASS`.

> Assign to a test policy and run in **Detect** mode for 1–2 weeks before
> promoting to **Block**. All patterns are Custom IOA regex (RE2), not CQL.

| # | Rule type | Severity | Image Filename | Command Line |
|---|---|---|---|---|
| IOA-1 | Process Creation | High | `.*\\rundll32\.exe` | `(?i).*comsvcs(\.dll)?.*(MiniDump\|#\s*\+?\s*24).*` |
| IOA-2 | Process Creation | High | `.*\\procdump(64)?\.exe` | `(?i).*\blsass\b.*` |
| IOA-3 | Process Creation | Critical | *(any)* | `(?i).*(nanodump\|handlekatz\|dumpert\|pypykatz\|lsassy\|mimikatz\|sekurlsa).*` |
| IOA-4 | Process Creation | Medium | `.*\\(cmd\|powershell\|pwsh\|rundll32)\.exe` | *(any)* — with **Parent Image** `.*\\lsass\.exe` |

IOA-4 is deliberately Medium: WerFault is a common benign LSASS child, so treat
it as correlation input rather than a block candidate.
