# Elastic — Session Token Reuse From Multiple Browsers / Locations (T1550.004)

**Technique:** T1550.004 — Use Alternate Authentication Material: Web Session Cookie
**Tactic:** Defense Evasion (TA0005) · Lateral Movement (TA0008) · Credential Access (TA0006, via T1539)
**Author:** Keith M · **Version:** 1.1 · **Updated:** 2026-07-28
**Spec:** [`../specs/T1550.004_session_token_reuse.md`](../specs/T1550.004_session_token_reuse.md)
**Min stack:** 8.15 (`ST_DISTANCE` for geo-velocity); 8.11 for ES|QL rules generally

### Alert conditions (all required — spec §2.1)

| | Condition |
|---|---|
| R1 | Same session identifier |
| R2 | Same user |
| R3 | ≥2 distinct **normalised browser families** |
| R4 | ≥2 distinct ASNs / source networks |
| R5 | Within a 60-minute window |
| R6 | No suppression match (spec §2.3) |

---

## Language selection — read this before implementing

**This detection is an aggregation, and KQL cannot aggregate.** A KQL rule can
only ask "does this single document match", so it cannot express "this session
was seen with two different browsers". Attempting it in KQL alone produces
either nothing or an alert on every session.

So:

| Language | Role here | Why |
|---|---|---|
| **ES\|QL** | **Primary — the actual detection** | `STATS COUNT_DISTINCT(...) BY session.id` is exactly the required shape |
| **KQL** | Candidate surfacing + Threshold-rule scaffolding | Kibana's Threshold rule type adds a cardinality check on top of a KQL filter |
| **EQL** | Narrow sequence cases only | EQL joins on field *equality*; it cannot express "browser differs from the previous event". Do not force it. |

The honest answer is that ES|QL is the right tool and the other two are
supporting. Both are included because you asked for all three, with their real
limits stated rather than papered over.

## 1. Entra ID / Azure AD (`logs-azure.signinlogs-*`)

### 1.1 ES|QL — primary detection

```esql
FROM logs-azure.signinlogs-*
| WHERE azure.signinlogs.properties.session_id IS NOT NULL
    AND event.outcome == "success"
    // scope to browser sign-ins; "Mobile Apps and Desktop clients" etc. are
    // client_app_used values, not device_detail.browser values (spec §4.1)
    AND azure.signinlogs.properties.client_app_used == "Browser"
// --- normalise browser to family (spec §3.1); Entra gives "Chrome 126.0.0" ---
| EVAL browser_family = TO_LOWER(SPLIT(azure.signinlogs.properties.device_detail.browser, " ")),
       os_family      = TO_LOWER(azure.signinlogs.properties.device_detail.operating_system)
| EVAL browser_fp = CONCAT(MV_FIRST(browser_family), ":", os_family)
| STATS n_browsers = COUNT_DISTINCT(browser_fp),
        n_asns     = COUNT_DISTINCT(azure.signinlogs.properties.autonomous_system_number),
        n_countries= COUNT_DISTINCT(source.geo.country_iso_code),
        n_devices  = COUNT_DISTINCT(azure.signinlogs.properties.device_detail.device_id),
        browsers   = VALUES(browser_fp),
        ips        = VALUES(source.ip),
        countries  = VALUES(source.geo.country_iso_code),
        first_seen = MIN(@timestamp),
        last_seen  = MAX(@timestamp),
        events     = COUNT(*)
    BY azure.signinlogs.properties.session_id, azure.signinlogs.properties.user_principal_name
// --- R3 + R4: the alert condition ---
| WHERE n_browsers >= 2 AND n_asns >= 2
// --- R5: 60-minute window ---
| EVAL window_s = DATE_DIFF("seconds", first_seen, last_seen)
| WHERE window_s <= 3600
// --- severity (spec §2.4) ---
| EVAL severity = CASE(
    n_countries >= 2 AND n_devices >= 2, "critical",
    n_countries >= 2,                    "high",
    "medium")
| KEEP severity, azure.signinlogs.properties.user_principal_name,
       azure.signinlogs.properties.session_id, browsers, ips, countries,
       n_devices, events, window_s, first_seen, last_seen
| SORT severity ASC, events DESC
```

### 1.2 Geo-velocity (E1) — compute as an enrichment, not in the STATS

**`MIN`/`MAX` do not aggregate a `geo_point`**, and ES|QL `STATS` has no
first-by-time / last-by-time over a point, so impossible-travel cannot be
computed inside the §1.1 aggregation. Do not write `pt_first = MIN(source.geo.location)`
— it does not return the earliest point and the rule will error.

Compute velocity as a second step on the sessions §1.1 already flagged, using
the **numeric** coordinate fields (not the `geo_point`), which `MIN`/`MAX` do
aggregate. This is an approximation — `MIN`/`MAX` give the bounding box, not the
strictly earliest and latest fix — which is sufficient for a >900 km/h gate:

```esql
FROM logs-azure.signinlogs-*
| WHERE azure.signinlogs.properties.session_id IS NOT NULL
| EVAL lat = azure.signinlogs.properties.location.geo_coordinates.latitude,
       lon = azure.signinlogs.properties.location.geo_coordinates.longitude
| STATS lat1 = MIN(lat), lat2 = MAX(lat),
        lon1 = MIN(lon), lon2 = MAX(lon),
        first_seen = MIN(@timestamp),
        last_seen  = MAX(@timestamp)
    BY azure.signinlogs.properties.session_id
// haversine on the numeric extremes
| EVAL dist_km = 6371 * ACOS(LEAST(1.0,
      SIN(lat1*PI()/180)*SIN(lat2*PI()/180) +
      COS(lat1*PI()/180)*COS(lat2*PI()/180)*COS((lon2-lon1)*PI()/180)))
| EVAL hours = DATE_DIFF("seconds", first_seen, last_seen) / 3600.0
| EVAL velocity_kmh = dist_km / GREATEST(hours, 0.0167)
| WHERE velocity_kmh > 900
| SORT velocity_kmh DESC
```

Verify the coordinate field paths against your azure integration mapping before
deploying.

### 1.3 KQL — candidate filter for a Threshold rule

Use Kibana rule type **Threshold**, group by `session_id`, with
*Cardinality*: `device_detail.browser` ≥ 2. The KQL below is only the filter —
the cardinality condition is set in the rule UI, not in the query.

```kql
event.dataset : "azure.signinlogs"
and azure.signinlogs.properties.session_id : *
and event.outcome : "success"
and not source.ip : (
      "10.0.0.0/8" or "172.16.0.0/12" or "192.168.0.0/16"
    )
and azure.signinlogs.properties.client_app_used : "Browser"
```

## 2. Okta (`logs-okta.system-*`)

`dtHash` is Okta's device token — a change while `externalSessionId` holds
constant is one of the cleanest hijack signals available (spec §4.2, E8).

### 2.1 ES|QL — primary

```esql
FROM logs-okta.system-*
| WHERE okta.authentication_context.external_session_id IS NOT NULL
| EVAL browser_fp = CONCAT(TO_LOWER(okta.client.user_agent.browser), ":",
                           TO_LOWER(okta.client.user_agent.os))
| WHERE browser_fp NOT LIKE "unknown*" AND browser_fp NOT LIKE "*service*"
| STATS n_browsers      = COUNT_DISTINCT(browser_fp),
        n_asns          = COUNT_DISTINCT(okta.security_context.as_number),
        n_countries     = COUNT_DISTINCT(okta.client.geographical_context.country),
        n_device_tokens = COUNT_DISTINCT(okta.debug_context.debug_data.dt_hash),
        browsers        = VALUES(browser_fp),
        ips             = VALUES(okta.client.ip),
        countries       = VALUES(okta.client.geographical_context.country),
        proxy_seen      = VALUES(okta.security_context.is_proxy),
        first_seen      = MIN(@timestamp),
        last_seen       = MAX(@timestamp),
        events          = COUNT(*)
    BY okta.authentication_context.external_session_id, okta.actor.alternate_id
| WHERE n_browsers >= 2 AND n_asns >= 2
| EVAL window_s = DATE_DIFF("seconds", first_seen, last_seen)
| WHERE window_s <= 3600
| EVAL severity = CASE(
    n_device_tokens >= 2 AND n_countries >= 2, "critical",
    n_device_tokens >= 2,                      "high",
    n_countries >= 2,                          "high",
    "medium")
| KEEP severity, okta.actor.alternate_id,
       okta.authentication_context.external_session_id,
       browsers, ips, countries, n_device_tokens, proxy_seen,
       events, window_s, first_seen, last_seen
| SORT severity ASC
```

### 2.2 EQL — proxied admin access on an existing session

A legitimate EQL sequence: the join key (`external_session_id`) stays equal
while a later event on that session comes through a proxy — a replay-shaped
pattern.

```eql
sequence by okta.authentication_context.external_session_id with maxspan=1h
  [ any where event.dataset == "okta.system"
      and event.action : ("user.session.start", "user.authentication.sso") ]
  [ any where event.dataset == "okta.system"
      and event.action : "user.session.access_admin_app"
      and okta.security_context.is_proxy == true ]
```

> This is **not** the dtHash-change detection. EQL joins on field *equality* and
> cannot compare a field to its own earlier value, so "same session, *different*
> dtHash" is not expressible in EQL. That signal is the
> `COUNT_DISTINCT(...dt_hash) >= 2` in the ES|QL rule at §2.1 (E8) — use that.

## 3. Lab web app + reverse proxy (Juice Shop / flask-sqli)

The only source with **JA3/JA4**, and therefore the only one that catches an
attacker who copies the victim's User-Agent (spec §3.3, E7). Session cookie is
HMAC-hashed at the proxy — never index it raw (spec §3.2).

### 3.1 ES|QL — browser OR TLS-fingerprint divergence

```esql
FROM logs-nginx.access-*, logs-juiceshop-*
| WHERE session.key IS NOT NULL
| EVAL browser_fp = CONCAT(TO_LOWER(user_agent.name), ":", TO_LOWER(user_agent.os.name))
| STATS n_browsers  = COUNT_DISTINCT(browser_fp),
        n_ja4       = COUNT_DISTINCT(tls.client.ja4),
        n_ips       = COUNT_DISTINCT(source.ip),
        n_countries = COUNT_DISTINCT(source.geo.country_iso_code),
        browsers    = VALUES(browser_fp),
        ja4s        = VALUES(tls.client.ja4),
        ips         = VALUES(source.ip),
        paths       = VALUES(url.path),
        first_seen  = MIN(@timestamp),
        last_seen   = MAX(@timestamp),
        events      = COUNT(*)
    BY session.key, user.name
// R3 satisfied by a browser-family change OR a TLS-stack change
| WHERE (n_browsers >= 2 OR n_ja4 >= 2) AND n_ips >= 2
| EVAL window_s = DATE_DIFF("seconds", first_seen, last_seen)
| WHERE window_s <= 3600
// E7 — UA identical but TLS stack differs: deliberate spoofing, escalate hard
| EVAL ua_spoof_suspected = n_browsers == 1 AND n_ja4 >= 2
| EVAL severity = CASE(
    ua_spoof_suspected,                   "critical",
    n_browsers >= 2 AND n_countries >= 2, "critical",
    n_browsers >= 2,                      "high",
    "medium")
| KEEP severity, user.name, session.key, browsers, ja4s, ua_spoof_suspected,
       ips, paths, events, window_s, first_seen, last_seen
| SORT severity ASC
```

### 3.2 EQL — token replayed by a non-browser client

Catches the crude case: cookie lifted into `curl`/`python-requests` rather than
a real browser.

```eql
sequence by session.key with maxspan=1h
  [ any where user_agent.name : ("Chrome", "Firefox", "Safari", "Edge") ]
  [ any where user_agent.name : ("curl", "python-requests", "Go-http-client",
                                 "okhttp", "PostmanRuntime", "wget")
      or user_agent.original == null ]
```

### 3.3 KQL — hunt for non-browser clients holding a session

```kql
session.key : * and (
  user_agent.name : ("curl" or "python-requests" or "Go-http-client" or
                     "okhttp" or "PostmanRuntime" or "wget")
  or not user_agent.original : *
)
```

## 4. Generic / ECS-normalised

Portable across any source mapped to ECS. Least precise — verify `session.id`
is populated consistently before relying on it.

```esql
FROM logs-*
| WHERE session.id IS NOT NULL AND user.name IS NOT NULL
| EVAL browser_fp = CONCAT(TO_LOWER(user_agent.name), ":", TO_LOWER(user_agent.os.name))
| STATS n_browsers  = COUNT_DISTINCT(browser_fp),
        n_ips       = COUNT_DISTINCT(source.ip),
        n_countries = COUNT_DISTINCT(source.geo.country_iso_code),
        n_asns      = COUNT_DISTINCT(source.as.number),
        browsers    = VALUES(browser_fp),
        ips         = VALUES(source.ip),
        countries   = VALUES(source.geo.country_iso_code),
        first_seen  = MIN(@timestamp),
        last_seen   = MAX(@timestamp),
        events      = COUNT(*)
    BY session.id, user.name
| WHERE n_browsers >= 2 AND n_asns >= 2
| EVAL window_s = DATE_DIFF("seconds", first_seen, last_seen)
| WHERE window_s <= 3600
| EVAL severity = CASE(n_countries >= 2, "high", "medium")
| SORT severity ASC, events DESC
```

## Deployment

- **Rule type:** ES|QL · **Interval:** 15m · **Look-back:** 70m
  (overlap the 60-minute correlation window so boundary-spanning sessions
  are not missed)
- **Risk score:** 73 · **Severity:** high
- **Suppress alerts by:** `session.id` — otherwise one hijacked session alerts
  on every subsequent run
- **Required enrichment:** GeoIP and ASN ingest processors on `source.ip`;
  `user_agent` ingest processor for parsing

### Suppression lists to build first (spec §2.3)

Index these as enrich policies and add matching `WHERE NOT` clauses — the rule
is not production-ready without them:

`corporate_egress_ranges` (S1) · `mobile_carrier_asns` (S2) ·
`icloud_private_relay` (S3, refresh weekly) · `service_user_agents` (S5) ·
`approved_travel_users` (S7)

## Response

**Revoke the session first.** A password reset does not invalidate an existing
session token — the attacker keeps their access. Full procedure in spec §6.

## Validation

Lab procedure in spec §7 — authenticate to Juice Shop from Firefox on Kali,
lift `connect.sid`, replay from Chrome on a different VLAN, confirm the rule
fires at High. Then repeat with a spoofed matching UA to confirm §3.1 still
catches it on JA4 alone.
