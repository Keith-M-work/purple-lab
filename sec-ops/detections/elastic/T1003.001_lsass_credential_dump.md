# Elastic — LSASS Credential Dumping (T1003.001)

**Technique:** T1003.001 — OS Credential Dumping: LSASS Memory
**Tactic:** Credential Access (TA0006)
**Platform:** Windows
**Author:** Keith M · **Version:** 2.0 · **Updated:** 2026-07-24
**Data source:** Sysmon EID 10 / EID 1 via Elastic Agent or Winlogbeat
**Indices:** `winlogbeat-*`, `logs-windows.sysmon_operational-*`, `logs-endpoint.events.*`
**Min stack:** 8.12 (ES|QL detection rules require 8.11+)

Three query languages, each a first-class artifact. They are not translations of
one another — each is used where it is strongest:

| Language | Use for | Rule type |
|---|---|---|
| **KQL** | The single-event handle-access detection | `query` |
| **EQL** | Ordered sequences (dump → artifact) | `eql` |
| **ES|QL** | Aggregation, thresholds, hunting, dashboards | `esql` |

Access masks used throughout — `0x1010`, `0x1410`, `0x1438`, `0x143a`, `0x147a`,
`0x1f0fff`, `0x1f1fff`, `0x1fffff`.

---

## 1. KQL — LSASS handle access (Sysmon EID 10)

```kql
event.code : "10"
and winlog.event_data.TargetImage : *\\lsass.exe
and winlog.event_data.GrantedAccess : (
      "0x1010" or "0x1410" or "0x1438" or "0x143a"
      or "0x147a" or "0x1f0fff" or "0x1f1fff" or "0x1fffff"
    )
and not winlog.event_data.SourceImage : (
      *\\WerFault.exe or *\\WerFaultSecure.exe or *\\MsMpEng.exe
    )
```

Variant catching injected/unbacked dumping code regardless of mask:

```kql
event.code : "10"
and winlog.event_data.TargetImage : *\\lsass.exe
and winlog.event_data.CallTrace : *UNKNOWN*
and not winlog.event_data.SourceImage : (*\\WerFault.exe or *\\WerFaultSecure.exe)
```

## 2. EQL — tooling and sequences

Command-line dumping tooling (Sysmon EID 1):

```eql
process where event.code == "1" and
(
  (process.name : "rundll32.exe" and
     process.command_line : "*comsvcs*" and
     process.command_line : ("*MiniDump*", "*#24*")) or
  (process.name : ("procdump.exe", "procdump64.exe") and
     process.command_line : "*lsass*") or
  process.command_line : (
     "*nanodump*", "*handlekatz*", "*dumpert*", "*pypykatz*",
     "*lsassy*", "*sekurlsa*", "*mimikatz*", "*safetykatz*")
)
```

Sequence — dump command followed by a `.dmp` write on the same host. This is the
detection EQL exists for; neither half alone is high confidence.

```eql
sequence by host.id with maxspan=5m
  [ process where event.code == "1" and
      process.command_line : "*lsass*" and
      process.command_line : ("*comsvcs*", "*procdump*", "*MiniDump*", "*nanodump*") ]
  [ file where event.action == "creation" and file.extension : "dmp" ]
```

Sequence — LSASS handle access followed by a `.dmp` write, joined on the
accessing process:

```eql
sequence by host.id with maxspan=2m
  [ any where event.code == "10" and
      winlog.event_data.TargetImage : "*\\lsass.exe" and
      winlog.event_data.GrantedAccess : ("0x1010", "0x1410", "0x1438", "0x143a", "0x1fffff") ]
  [ file where file.extension : "dmp" ]
```

## 3. ES|QL — hunting, aggregation and thresholds

Rank LSASS-accessing processes by volume; unfamiliar `SourceImage` values at the
top of this list are the hunt.

```esql
FROM winlogbeat-*, logs-windows.sysmon_operational-*
| WHERE event.code == "10"
    AND ENDS_WITH(winlog.event_data.TargetImage, "\\lsass.exe")
    AND winlog.event_data.GrantedAccess IN (
          "0x1010", "0x1410", "0x1438", "0x143a",
          "0x147a", "0x1f0fff", "0x1f1fff", "0x1fffff")
    AND NOT winlog.event_data.SourceImage RLIKE ".*\\\\(WerFault|WerFaultSecure|MsMpEng)\\.exe"
| STATS hits = COUNT(*),
        hosts = COUNT_DISTINCT(host.name),
        masks = VALUES(winlog.event_data.GrantedAccess)
    BY winlog.event_data.SourceImage
| SORT hits ASC
```

> `SORT hits ASC` is deliberate — in credential-access hunting the *rare* source
> process is the interesting one. AV and backup agents dominate the high end.

Threshold rule — a single host accessing LSASS from many distinct processes:

```esql
FROM winlogbeat-*, logs-windows.sysmon_operational-*
| WHERE event.code == "10" AND ENDS_WITH(winlog.event_data.TargetImage, "\\lsass.exe")
| STATS distinct_sources = COUNT_DISTINCT(winlog.event_data.SourceImage) BY host.name
| WHERE distinct_sources > 5
| SORT distinct_sources DESC
```

Command-line tooling, aggregated by user and host:

```esql
FROM winlogbeat-*, logs-windows.sysmon_operational-*
| WHERE event.code == "1"
    AND process.command_line RLIKE "(?i).*(nanodump|handlekatz|dumpert|pypykatz|lsassy|sekurlsa|mimikatz|comsvcs.*minidump|procdump.*lsass).*"
| STATS hits = COUNT(*), cmds = VALUES(process.command_line)
    BY host.name, user.name, process.name
| SORT hits DESC
```

## False positives

- WerFault / WerFaultSecure dumping a crashing LSASS — filtered in every query above.
- AV/EDR (`MsMpEng.exe`), backup and DLP agents.
- IR tooling and this lab's own validation runs.

## Deployment

Create as Kibana detection rules — Security → Rules → Create new rule — choosing
**Custom query** (KQL), **Event Correlation** (EQL) or **ES|QL** to match the
block used. `risk_score: 73`, `severity: high`, `interval: 5m`, `from: now-9m`
for the KQL and EQL rules.
